TipLihat contoh pengisian
Buka contoh fiktif Minggu 4 untuk melihat tingkat kekonkretan evidence dan analisis. Jangan menyalin contoh sebagai evidence pribadi.
Core Meaning
Modus undangan palsu memanfaatkan file APK yang dikirim melalui chat dan dibuat seolah-olah sebagai dokumen biasa. Menerima file tidak berarti aplikasi langsung terpasang. Risiko meningkat ketika penerima memasang APK tersebut dan memberikan izin akses. Aplikasi berbahaya dapat mencoba membaca data sensitif seperti SMS, notifikasi, atau OTP dan menggunakannya untuk penipuan finansial. Karena itu, penerima perlu memeriksa jenis file serta pengirimnya dan tidak memasang APK yang dikirim melalui chat.
Core meaning tersebut mengacu pada penjelasan Bank Indonesia mengenai penipuan file APK dan panduan Google mengenai aplikasi berbahaya serta restricted settings.
Konteks dan Peta Target
Saya menempatkan diri sebagai mahasiswa STI yang menyusun pesan edukasi keamanan digital. Kelima target berada dalam situasi yang berbeda meskipun menerima core meaning yang sama. Teman membutuhkan peringatan personal, rekan STI membutuhkan mekanisme teknis, ketua organisasi membutuhkan kebijakan untuk anggotanya, nasabah mobile banking membutuhkan langkah penanganan, dan pengguna WhatsApp secara umum membutuhkan peringatan yang singkat.

Alasan Adaptasi
Friend (teman dekat pengguna WhatsApp)
“San, hati-hati kalau dapat file undangan lewat WhatsApp. Cek dulu tipe filenya. Kalau ternyata APK, jangan diinstal meskipun nama atau tampilannya seperti PDF. Aplikasi itu bisa meminta izin untuk membaca SMS, notifikasi, atau OTP. Hapus filenya dan konfirmasi langsung ke pengirim.”
Menggunakan bahasa santai, contoh WhatsApp, dan tindakan langsung karena hubungannya dekat. Istilah teknis dibatasi pada APK, SMS, dan OTP yang umum dikenali.
Technical peer (rekan mahasiswa STI)
“Modus undangan palsu memakai social engineering untuk mendorong korban melakukan sideload APK dari aplikasi pesan. File yang diterima tidak otomatis mengeksekusi kode. Risiko muncul setelah instalasi dan pemberian permission, misalnya akses SMS, notifikasi, atau Accessibility. Mitigasinya adalah memblokir instalasi dari sumber tidak dikenal, mengaktifkan Play Protect, memeriksa permission, dan memverifikasi sumber file.”
Istilah sideload, permission, Accessibility, dan Play Protect digunakan karena target memiliki pengetahuan teknis. Penjelasan menekankan tahapan serangan dan mekanisme mitigasi.
Manager (ketua organisasi kampus)
“File undangan palsu yang dikirim melalui chat dapat membahayakan perangkat pribadi maupun data organisasi jika anggota memasang APK dan memberikan izin akses. Dampaknya dapat mencakup kebocoran OTP, notifikasi, atau dokumen kerja. Organisasi perlu melarang pemasangan APK dari chat, meminta anggota mengaktifkan Play Protect, dan menyediakan jalur pelaporan ketika ada file mencurigakan.”
Ketua organisasi membutuhkan gambaran risiko, dampak terhadap anggota, dan keputusan yang dapat diterapkan. Detail teknis dibatasi pada hal yang diperlukan untuk menetapkan aturan.
Customer (nasabah mobile banking)
“Jika Anda menerima file undangan melalui chat, periksa nama dan jenis filenya sebelum membuka atau memasangnya. Jangan instal file berakhiran APK dari sumber yang tidak dikenal. Jika sudah terlanjur memasang aplikasi mencurigakan, putuskan koneksi internet, hapus aplikasinya, dan segera hubungi bank melalui kanal resmi.”
Nasabah membutuhkan instruksi yang berurutan dan mudah dilakukan. Fokusnya adalah mencegah kerugian dan memberi langkah awal jika aplikasi sudah terpasang.
Public (pengguna WhatsApp dan Android)
“Waspada undangan palsu lewat chat. File yang terlihat seperti dokumen dapat berupa APK berbahaya. Jangan memasang APK dari pengirim yang tidak terverifikasi, periksa jenis file, dan gunakan aplikasi dari toko resmi. Jika terlanjur memasangnya, putuskan koneksi internet dan hubungi bank melalui kanal resmi.”
Pengguna umum membutuhkan pesan ringkas tanpa banyak jargon serta tindakan yang dapat dilakukan segera.
Konsistensi Meaning
Kelima versi mempertahankan empat fakta yang sama:
Pelaku menyamarkan atau mempresentasikan APK sebagai undangan atau dokumen.
File tidak langsung memasang dirinya hanya karena diterima melalui chat.
Risiko meningkat setelah APK dipasang dan mendapatkan izin akses.
Penerima perlu memeriksa file, tidak memasang APK dari chat, dan mengambil tindakan jika sudah terlanjur memasangnya.
Perubahannya berada pada pilihan istilah, tingkat detail, contoh, dan tindakan yang paling relevan bagi setiap target.
Feedback Understanding
Versi friend diuji kepada seorang teman dekat yang menggunakan WhatsApp dan perangkat Android. Setelah membaca pesannya, teman tersebut memberikan feedback:
“ohh pahamm paham, berarti bahayanya tuh kalo aplikasinya udah diinstal kan, kalo masih nerima file di whatsapp doang belum bahaya. okedehh makasiih banyak infonya sann”
Feedback tersebut menunjukkan bahwa target bukan hanya menyatakan paham, tetapi juga dapat menjelaskan kembali bahwa risiko utama muncul setelah APK dipasang. Target juga dapat membedakan antara sekadar menerima file di WhatsApp dan memasang aplikasi. Karena core meaning diterima dengan tepat, saya mempertahankan pilihan bahasa dan panjang versi friend.
Evidence
Evidence utama Week 4 ini adalah lima versi pesan pada tabel dan kutipan feedback dari target versi friend. Tautan Bank Indonesia dan Google berfungsi sebagai sumber pemeriksaan fakta teknis, bukan sebagai pengganti feedback target. Tidak ada screenshot yang digunakan. Feedback dicatat sebagai kutipan dari percakapan chat.

Evidence dan Analisis
Person & character
Target dipetakan secara konkret: teman dekat pengguna WhatsApp, rekan mahasiswa STI, ketua organisasi kampus, nasabah mobile banking, dan pengguna WhatsApp atau Android secara umum. Kebutuhan informasi mereka dibedakan tanpa mengubah fakta dasarnya.
Objective & state
State awal setiap target berbeda. Teman dan public perlu mengenali modus, technical peer perlu memahami mekanisme, manager perlu menentukan aturan, sedangkan customer perlu mengetahui langkah penanganan. State tujuannya adalah setiap target memahami risiko dan tindakan yang sesuai dengan perannya.
Repertoire & language
Repertoire berubah dari peringatan personal, penjelasan teknis, ringkasan risiko organisasi, instruksi untuk nasabah, hingga pengumuman publik. Batas teknis bahwa file tidak otomatis terpasang tetap dipertahankan dan klaim diperiksa menggunakan sumber terkait.
Response & adaptation
Respons teman menunjukkan bahwa ia dapat membedakan tahap menerima file dan memasang APK. Karena core meaning dipahami dengan tepat, versi friend dipertahankan.
Agreement & action
Setiap versi memiliki tindakan yang jelas, seperti tidak memasang APK, memeriksa sumber, mengaktifkan perlindungan, atau menghubungi bank. Feedback target membuktikan pemahaman, tetapi belum membuktikan apakah tindakan tersebut akan dijalankan.
Relationship outcome
Versi friend menggunakan nada peringatan yang tetap akrab dan tidak menyalahkan target. Respons teman menunjukkan bahwa pesan diterima tanpa menimbulkan ketegangan.
Penggunaan AI
AI digunakan untuk membantu membedakan tingkat detail pada lima target dan memeriksa konsistensi core meaning. Saya tetap memeriksa klaim teknis menggunakan sumber Bank Indonesia dan Google.
Feedback dan Tindak Lanjut
Feedback yang diterima: “ohh pahamm paham, berarti bahayanya tuh kalo aplikasinya udah diinstal kan, kalo masih nerima file di whatsapp doang belum bahaya. okedehh makasiih banyak infonya sann” dari target versi friend.
Adaptation/replay: Target dapat menjelaskan kembali bahwa risiko muncul setelah aplikasi dipasang, bukan saat file hanya diterima. Karena meaning dipahami dengan tepat, versi friend dipertahankan.
Next practice: Setelah memeriksa pemahaman, saya akan melanjutkan dengan pertanyaan singkat mengenai tindakan yang akan dilakukan target jika menerima file serupa.
