Kompetensi Target
Membedakan person, personality, dan character serta memilih objective, repertoire, dan language yang sesuai dengan konteks komunikasi interpersonal dan akademik.

Risiko & Tindakan Pencegahan
1. Intra-Self (Diri Sendiri)
Diri sendiri setelah evaluasi draf tugas
Reflective Learner
Memisahkan kesalahan teknis dari identitas diri; mengevaluasi fakta secara objektif.
Jurnal evaluasi berbasis fact vs story; register bahasa introspektif dan netral.
Terjebak self-blame; mewajibkan pencatatan 3 data fakta sebelum mengambil kesimpulan.
2. Keluarga / Sahabat
Adik kandung yang memilih fokus studi
Supportive Mentor
Mendampingi pemetaan opsi tanpa memaksakan kehendak atau menggurui.
Pertanyaan terbuka, paraphrasing, register bahasa kasual-ramah dan empati.
Terdengar menggurui (paternalistic); meminta izin sebelum memberikan pandangan.
3. Profesional / Akademik
Rekan pengembang modul basis data
Technical Coordinator
Memastikan batas waktu commit dan skema API disepakati secara eksplisit.
Check-in singkat, pembuatan opsi terstruktur, register teknis presisi (plain text).
Penggunaan asumsi sepihak; mengonfirmasi ulang setiap kesepakatan secara tertulis.
4. Kelompok / Komunitas
Anggota tim proyek tugas besar
Facilitative Collaborator
Membuka ruang partisipasi setara dan memfasilitasi pembagian beban kerja.
Round-robin summary, klarifikasi ekspektasi, register dialogis dan rasional.
Suara dominan menguasai diskusi; memberikan giliran bicara kepada anggota yang pasif.
5. Dunia / Publik
Pembaca umum / Pengguna sistem
Clear Knowledge Translator
Menyampaikan gagasan teknis menjadi langkah praktis yang relevan dan mudah dipahami.
Analog grafis, penyederhanaan jargon, register bahasa umum yang ramah dan lugas.
Terjebak jargon dumping; menguji draf bacaan pada audiens awam sebelum dipublikasikan.
2. Pembedaan Konseptual & Perubahan Register Bahasa
Membedakan Person, Personality, dan Character
Person: Individu nyata utuh dengan segala kompleksitas dan latar belakangnya (misalnya: Rekan Fakhri sebagai anggota tim proyek pengembang perangkat lunak).
Personality: Kecenderungan sifat atau temperamen bawaan individu yang relatif stabil (misalnya: Fakhri cenderung introvert, analitis, dan berhati-hati dalam menyampaikan pendapat).
Character: Peran komunikasi deliberatif yang diambil oleh person pada konteks dan sasaran tertentu untuk mencapai objective spesifik (misalnya: Fakhri mengambil peran Backend Specialist saat berdiskusi teknis, sementara saya mengambil peran Technical Coordinator).
Demonstrasi Perubahan Register Bahasa
Ketika mengomunikasikan masalah penundaan commit basis data: * Ke Character Teman (Informal/Kasual):
> “Ri, aman kan? Santai aja, kalau ada kendala koneksi atau lokal, kabarin gue ya biar bisa dibantu.” * Ke Character Technical Coordinator (Profesional/Eksplisit):
> “Fakhri, berdasarkan catatan jadwal jam 13.00 WIB draf skema basis data belum terunggah di repositori main. Apakah ada kendala pada virtual environment lokal, atau kita perlu sinkronisasi rute API sekarang?”
3. Bukti Artefak Verifikasi Langsung (Inline Plain Text)
Seluruh artefak pendukung disajikan secara penuh di bawah ini dalam format teks mentah tanpa tautan luar agar dapat diverifikasi secara independen oleh assessor.
A. Transkrip Percakapan Teknis Verbatim
[14.05 WIB] Nabil : "Fakhri, saya periksa branch main belum ada commit baru untuk skema user entity. Apakah ada kendala di lingkungan lokal?"
[14.08 WIB] Fakhri : "Iya Bil, maaf banget. Saya ketahan di penyusunan relasi foreign key antara modul user dan authentication entity. Takut bentrok sama skema kamu."
[14.11 WIB] Nabil : "Terima kasih infonya. Kita pisahkan skema auth ke tabel terisolasi dulu saja supaya kamu tidak terhambat. Bagaimana kalau kamu push draf mentahnya dalam 10 menit?"
[14.13 WIB] Fakhri : "Setuju. Saya isolasi tabel auth-nya lalu push sekarang."
B. Perbandingan Skema Basis Data (Sebelum vs Sesudah Commit)
Skema Sebelum Commit (Draf Lokal Mendasar - Terhambat Dependency Conflict):
-- Draf Awal (Lokal - Terhambat Konflik Relasi)
CREATE TABLE users (
user_id INT PRIMARY KEY,
username VARCHAR(50),
auth_token TEXT, -- Tergabung langsung, memicu keraguan struktur
created_at TIMESTAMP
);
Skema Sesudah Commit (Terisolasi & Disetujui Tim):
-- Skema Hasil Commit (Branch Main - Terverifikasi)
CREATE TABLE users (
user_id INT PRIMARY KEY,
username VARCHAR(50) NOT NULL,
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
CREATE TABLE auth_sessions (
session_id INT PRIMARY KEY,
user_id INT REFERENCES users(user_id) ON DELETE CASCADE,
auth_token TEXT NOT NULL,
expires_at TIMESTAMP NOT NULL
);
